L’**éditeur embarqué** affiche un document de Rocket Doc Fusion dans une page de **votre** application, dans une iframe : l’utilisateur relit et retouche le document fusionné sans changer d’outil. C’est ainsi que Rocket Dispatch montre chaque document avant de l’envoyer.

Le principe est celui du composeur de Rocket Mailer : votre serveur obtient un **jeton d’embed** de courte durée pour l’utilisateur connecté, et votre page le transmet à l’iframe par `postMessage`. Il n’y a pas encore de script `embed.js` : votre page implémente le protocole décrit ici, en quelques lignes.

## Ce qu’il vous faut

::steps{level="3"}

### Une application déclarée dans Rocket Doc Fusion

Dans **Administration → Applications**, un administrateur crée l’application, coche **Peut agir en tant qu’utilisateur** et déclare les **origines autorisées** : les origines des pages qui afficheront l’éditeur, par exemple `https://dispatch.exemple.com` (schéma, hôte et port, sans chemin ni `/` final). Il copie le jeton secret `rda_…`, affiché une seule fois, et note l’**identifiant** de l’application (UUID, non secret).

### Un endpoint sur votre serveur

Il identifie l’utilisateur connecté à **votre** application et demande pour lui un jeton d’embed, avec le secret de l’application. Le secret ne quitte jamais votre serveur.

### Le document

Il est créé par `POST /api/documents` au nom du même utilisateur (voir [Documents](/api/documents)). L’éditeur n’affiche que les documents de cet utilisateur.

::

## Le jeton d’embed

```http
POST /api/embed/token HTTP/1.1
Host: fusion.exemple.com
Authorization: Bearer rda_…
X-Impersonate-User: jean.dupont@exemple.com
Accept: application/json
```

```json [201 Created]
{
  "token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJSUzI1NiJ9…",
  "applicationId": "0199a1b2-7c3e-7d41-9f0a-4b2c6d8e1f23",
  "expiresAt": "2026-09-26T09:15:00+00:00"
}
```

Le jeton vaut 15 minutes (`EMBED_TOKEN_TTL`), pour un utilisateur et une application. Votre endpoint le renvoie au navigateur avec `Cache-Control: no-store`.

::caution
L’identité doit venir de **votre session**, jamais d’un paramètre envoyé par le navigateur. Un endpoint qui accepterait `?user=…` permettrait d’ouvrir les documents de n’importe quel collègue.
::

## L’iframe

```html
<iframe
  src="https://fusion.exemple.com/embed/editor?app=<applicationId>&document=<documentId>&mode=edit"
  title="Rocket Doc Fusion"
  allow="clipboard-read; clipboard-write; fullscreen"
  referrerpolicy="strict-origin"
  style="width: 100%; height: 80vh; border: 0"
></iframe>
```

| Paramètre | Rôle |
|---|---|
| `app` | Identifiant de l’application |
| `document` | Identifiant du document |
| `mode` | `edit` (défaut) ou `view` (lecture seule) |

L’éditeur occupe toute la hauteur de l’iframe : donnez-lui une hauteur fixe. L’iframe charge l’éditeur depuis `ONLYOFFICE_PUBLIC_URL` : cette adresse doit être joignable par le navigateur de l’utilisateur.

## Messages

Tous les messages sont des objets qui contiennent `source: 'rocket-doc-fusion'`.

### De l’iframe vers la page

| `type` | Données | Cible (`targetOrigin`) | Quand |
|---|---|---|---|
| `ready` | — | `*` | L’iframe a chargé la liste des origines autorisées et attend un jeton. |
| `token-request` | — | `*` | Le jeton a expiré : il en faut un nouveau. |
| `loaded` | — | origine de la page | La session est ouverte. |
| `resize` | `height: number` | origine de la page | La hauteur du contenu a changé (vous pouvez l’ignorer). |
| `document` | `document: { id, title, status, version, error }` | origine de la page | Le document est chargé. Pendant une fusion, l’iframe attend jusqu’à 2 minutes : `status` vaut alors `ready`, ou encore `merging` ou `failed`, et l’iframe affiche l’erreur. |
| `editor-ready` | — | origine de la page | L’éditeur ONLYOFFICE est affiché. |
| `saved` | `saved: boolean`, `version: number` | origine de la page | Réponse à `save`. `saved: true` : ONLYOFFICE enregistre, la version `version + 1` arrive quelques secondes plus tard. `saved: false` : rien n’était en cours d’édition. |

`ready` et `token-request` ne contiennent aucune donnée : ils peuvent être diffusés avant que l’iframe connaisse l’origine de la page. Les messages suivants ne sont envoyés **qu’à l’origine vérifiée** de la page.

### De la page vers l’iframe

| `type` | Données | Effet |
|---|---|---|
| `token` | `token: string` | Fournit le jeton d’embed. Réponse attendue à `ready` et `token-request`. |
| `save` | — | Force l’enregistrement des modifications en cours (`POST /api/documents/{id}/force-save`), par exemple avant d’envoyer le document. L’iframe répond par `saved`. |

::warning
Envoyez toujours le jeton avec l’origine de Rocket Doc Fusion comme `targetOrigin`, jamais `*`. L’iframe n’accepte un message que s’il vient de sa page parente, sur une origine autorisée.
::

## Implémentation minimale

```js [integration.js]
const FUSION = 'https://fusion.exemple.com'
const iframe = document.querySelector('#rocket-doc-fusion')

window.addEventListener('message', async (event) => {
  // N'écouter que l'iframe Rocket Doc Fusion
  if (event.origin !== FUSION || event.source !== iframe.contentWindow) return
  const message = event.data
  if (message?.source !== 'rocket-doc-fusion') return

  const send = data => iframe.contentWindow.postMessage({ source: 'rocket-doc-fusion', ...data }, FUSION)

  switch (message.type) {
    case 'ready':
    case 'token-request': {
      const { token } = await fetch('/rocket-doc-fusion/token', { method: 'POST' }).then(r => r.json())
      send({ type: 'token', token })
      break
    }
    case 'document':
      if (message.document.status === 'failed') console.error('Fusion en échec :', message.document.error)
      break
    case 'saved':
      console.log(message.saved ? `Version ${message.version + 1} en cours d'enregistrement` : 'Rien à enregistrer')
      break
  }
})

// Avant d'envoyer le document : enregistrer les retouches en cours
document.querySelector('#envoyer').addEventListener('click', () => {
  iframe.contentWindow.postMessage({ source: 'rocket-doc-fusion', type: 'save' }, FUSION)
})
```

Après `saved: true`, attendez que `GET /api/documents/{id}` renvoie une `version` supérieure avant de télécharger le document : c’est ONLYOFFICE qui envoie la nouvelle version, quelques secondes plus tard.

## Ce que peut faire l’iframe

Le jeton d’embed (`Authorization: Embed …`, jamais administrateur) n’ouvre que :

| Méthode | Endpoint | Usage |
|---|---|---|
| `GET` | `/api/me`, `/api/embed/context` | Utilisateur et application courants |
| `GET` | `/api/documents/{id}` | Le document et son statut |
| `GET` | `/api/documents/{id}/editor` | La configuration signée de l’éditeur ONLYOFFICE |
| `GET` | `/api/documents/{id}/content` | Le document en DOCX ou en PDF |
| `POST` | `/api/documents/{id}/force-save` | L’enregistrement forcé |

Il ne permet ni de lister, ni de créer, ni de supprimer des documents, ni d’ouvrir ceux d’un autre utilisateur. Tout autre endpoint répond `403`.

## Sécurité

- **Affichage limité à vos origines** : Rocket Doc Fusion envoie `Content-Security-Policy: frame-ancestors <vos origines>` ; ailleurs, le navigateur refuse d’afficher l’iframe.
- **Révocation immédiate** : désactiver l’application, ou lui retirer l’impersonation, coupe les éditeurs embarqués dès leur prochaine requête à l’API.
- **HTTPS** : votre page, Rocket Doc Fusion et ONLYOFFICE doivent être en HTTPS. Si votre application envoie un en-tête `Content-Security-Policy`, autorisez l’iframe : `frame-src https://fusion.exemple.com`.

## Variante : jeton dans le fragment d’URL

Pour un affichage ponctuel sans JavaScript côté page, le jeton peut être passé dans le **fragment** de l’URL, jamais envoyé aux serveurs et effacé par l’iframe dès sa lecture :

```html
<iframe src="https://fusion.exemple.com/embed/editor?app=<applicationId>&document=<documentId>#token=<jeton d'embed>"></iframe>
```

Sans renouvellement, l’enregistrement forcé échoue après 15 minutes, et les messages ne sont émis que si le navigateur expose l’origine de la page. Préférez `postMessage`.
