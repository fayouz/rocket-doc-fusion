Toutes les requêtes demandent un utilisateur : un JWT, ou une application qui impersonne un utilisateur (`Authorization: Bearer rda_…` + `X-Impersonate-User`). Voir [Authentification](/api/authentication).

Les documents sont **privés** : chacun ne voit que les siens, administrateurs compris. Pour les autres, un document n’existe pas (`404`).

## Fusionner

`POST /api/documents`, en `multipart/form-data` :

| Champ | Rôle | Défaut |
|---|---|---|
| `template` | Le modèle, au format DOCX (voir [Écrire un modèle](/templates/write-template)) | requis |
| `values` | Les valeurs, en **objet JSON** : `{"variable": "texte", "section": [{"champ": "texte"}]}` | `{}` |
| `title` | Nom du document | nom du modèle, sans `.docx` |

```bash [Terminal]
curl -X POST https://fusion.exemple.com/api/documents \
  -H "Authorization: Bearer rda_…" \
  -H "X-Impersonate-User: alice@exemple.com" \
  -H "Accept: application/json" \
  -F template=@devis.docx \
  -F title='Devis Société Martin' \
  -F 'values={"numero": "D-2026-042", "client_nom": "Société Martin", "lignes": [{"designation": "Audit de l’existant", "quantite": "1", "prix": "750,00 €"}], "total": "750,00 €"}'
```

La réponse (`202`) est le document, en cours de fusion : le worker le fusionne par ONLYOFFICE, en général en quelques secondes.

```json
{
  "id": "01a0c3f2-…",
  "title": "Devis Société Martin",
  "templateName": "devis.docx",
  "values": { "numero": "D-2026-042", "client_nom": "Société Martin", "lignes": [ … ], "total": "750,00 €" },
  "status": "merging",
  "error": null,
  "version": 0,
  "size": null,
  "editedAt": null,
  "ready": false,
  "ownerEmail": "alice@exemple.com",
  "applicationName": "Rocket Dispatch",
  "createdAt": "2026-09-26T10:12:00+00:00",
  "updatedAt": "2026-09-26T10:12:00+00:00",
  "createdBy": "alice@exemple.com",
  "updatedBy": "alice@exemple.com"
}
```

Les valeurs absentes sont remplacées par un texte vide ; les valeurs en trop sont ignorées. Les valeurs sont du texte : nombres et booléens (« oui », « non ») sont convertis, les objets ignorés.

| Erreur | Cause |
|---|---|
| `413` | Modèle trop gros (`DOC_FUSION_MAX_FILE_SIZE`, voir `GET /api/documents/settings`) |
| `422` | Le fichier n’est pas un DOCX, le modèle contient des erreurs (sections mal formées, décrites dans `detail`), ou `values` n’est pas un objet JSON |
| `403` | Application sans utilisateur (`X-Impersonate-User` manquant) |

`GET /api/documents/settings` renvoie la taille maximale : `{ "maxFileSize": 20971520 }`.

## Suivre la fusion

```bash [Terminal]
curl https://fusion.exemple.com/api/documents/01a0c3f2-… -H "Authorization: Bearer …" -H "Accept: application/json"
```

| `status` | Signification |
|---|---|
| `merging` | En cours de fusion. `version` vaut `0`. |
| `ready` | Fusionné (`ready: true`). `version` vaut `1` après la fusion, puis augmente à chaque enregistrement. `size` : la taille de la dernière version, `editedAt` : sa dernière retouche dans l’éditeur. |
| `failed` | La fusion a échoué : voir `error`. |

Interrogez le document toutes les secondes ou deux jusqu’à ce que `status` ne soit plus `merging`.

## Lister les documents

`GET /api/documents` liste les documents de l’utilisateur, les derniers modifiés en premier.

| Paramètre | Rôle |
|---|---|
| `title` | Recherche partielle dans le nom, sans tenir compte de la casse |
| `status` | `merging`, `ready` ou `failed` |
| `order[updatedAt]`, `order[createdAt]`, `order[title]` | Tri : `asc` ou `desc` |
| `page`, `itemsPerPage` | Pagination |

```bash [Terminal]
curl "https://fusion.exemple.com/api/documents?status=ready&order[title]=asc&itemsPerPage=50" \
  -H "Authorization: Bearer …" -H "Accept: application/json"
```

## Télécharger en Word ou en PDF

`GET /api/documents/{id}/content` renvoie la **dernière version** :

| Paramètre | Effet |
|---|---|
| — | Le document en DOCX, en pièce jointe |
| `format=pdf` | Le document converti en PDF par ONLYOFFICE, affiché dans le navigateur. La conversion est gardée en cache pour chaque version. |
| `download=1` | Le PDF en pièce jointe plutôt qu’affiché |

```bash [Terminal]
curl "https://fusion.exemple.com/api/documents/01a0c3f2-…/content?format=pdf" \
  -H "Authorization: Bearer …" -o devis.pdf
```

| Erreur | Cause |
|---|---|
| `409` | Le document n’est pas encore fusionné (ou la fusion a échoué) |
| `502` | ONLYOFFICE n’a pas pu convertir le document |

## Remplacer le contenu

`PUT /api/documents/{id}/content` (ou `POST`) remplace le document par un DOCX, envoyé tel quel dans le corps ou en `multipart/form-data` (champ `file`). C’est une **nouvelle version** ; les éditeurs ouverts sur le document repartent de ce contenu.

```bash [Terminal]
curl -X PUT https://fusion.exemple.com/api/documents/01a0c3f2-…/content \
  -H "Authorization: Bearer …" -H "Accept: application/json" \
  -H "Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document" \
  --data-binary @devis-corrigé.docx
```

La réponse est le document, avec sa nouvelle `version`. `422` si le contenu n’est pas un DOCX.

## Ouvrir l’éditeur

`GET /api/documents/{id}/editor?mode=edit` (ou `mode=view`) renvoie de quoi afficher l’éditeur ONLYOFFICE dans une page :

```json
{
  "scriptUrl": "https://office.exemple.com/web-apps/apps/api/documents/api.js",
  "config": {
    "document": { "fileType": "docx", "key": "…", "title": "Devis Société Martin.docx", "url": "…", "permissions": { "edit": true, … } },
    "documentType": "word",
    "editorConfig": { "mode": "edit", "lang": "fr", "callbackUrl": "…", "user": { "id": "…", "name": "Alice Durand" }, … },
    "token": "eyJ…"
  }
}
```

```html
<div id="editeur"></div>
<script src="<scriptUrl>"></script>
<script>
  new DocsAPI.DocEditor('editeur', config)
</script>
```

La configuration est **signée** pour ONLYOFFICE (`token`) : passez-la telle quelle, sans la modifier. `scriptUrl` vient de `ONLYOFFICE_PUBLIC_URL`. `409` si le document n’est pas encore fusionné. Pour afficher l’éditeur dans une autre application sans gérer ONLYOFFICE vous-même, utilisez plutôt l’[éditeur embarqué](/embed/editor).

Quand tous les éditeurs d’un document sont fermés, ONLYOFFICE renvoie le document modifié à Rocket Doc Fusion : c’est une nouvelle version, et l’éditeur suivant ouvre une nouvelle session.

## Forcer l’enregistrement

`POST /api/documents/{id}/force-save` demande aux éditeurs ouverts d’enregistrer tout de suite, par exemple avant d’envoyer le document :

| Réponse | Signification |
|---|---|
| `202` `{ "saved": true, "version": 2 }` | ONLYOFFICE enregistre : la version suivante (`3`) arrive quelques secondes plus tard. Les éditeurs restent ouverts. |
| `200` `{ "saved": false, "version": 2 }` | Rien n’est en cours d’édition : la version `2` est à jour. |

Après `saved: true`, attendez que `GET /api/documents/{id}` renvoie une `version` supérieure avant de télécharger le document.

## Supprimer

`DELETE /api/documents/{id}` supprime le document et **toutes ses versions** (`204`).

## Adresses réservées à ONLYOFFICE

ONLYOFFICE appelle l’API sur `/api/onlyoffice/documents/{id}/…` : `template` (le modèle), `merge.js` (le script Document Builder de la fusion), `versions/{n}` (une version) et `callback` (les enregistrements de l’éditeur). Ces adresses sont signées par Rocket Doc Fusion (`APP_SECRET`) et valables peu de temps, et le callback vérifie la signature d’ONLYOFFICE (`ONLYOFFICE_JWT_SECRET`). Vos applications n’ont pas à les appeler.
