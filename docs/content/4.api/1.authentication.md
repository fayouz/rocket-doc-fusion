L’API est servie sous `/api`. Sa documentation OpenAPI interactive est disponible sur `/api/docs`. Les réponses sont en JSON (`Accept: application/json`) ou en JSON-LD (`application/ld+json`) : envoyez toujours `Accept: application/json` depuis vos scripts.

## Utilisateur

```bash [Terminal]
curl -X POST https://fusion.exemple.com/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "alice@exemple.com", "password": "…"}'
# → { "token": "<jwt>" }
```

Le JWT est valable une heure et s’utilise avec `Authorization: Bearer <jwt>`. Les comptes LDAP se connectent avec leur mot de passe d’annuaire.

## Application

Un administrateur déclare l’application dans **Administration → Applications** et copie son jeton secret, affiché une seule fois :

```http
Authorization: Bearer rda_…
```

Seule, une application ne peut qu’appeler `GET /api/me`. Pour agir, elle **impersonne** un utilisateur :

```http
Authorization: Bearer rda_…
X-Impersonate-User: alice@exemple.com
```

Elle obtient alors les droits de cet utilisateur, **sauf** le rôle administrateur. Cela suppose que l’application ait l’option « Peut agir en tant qu’utilisateur ». C’est ainsi qu’une application [fusionne](/api/documents) au nom de ses utilisateurs : les documents sont les leurs, avec le nom de l’application.

```bash [Terminal]
curl -X POST https://fusion.exemple.com/api/documents \
  -H "Authorization: Bearer rda_…" \
  -H "X-Impersonate-User: alice@exemple.com" \
  -H "Accept: application/json" \
  -F template=@devis.docx \
  -F 'values={"client_nom": "Société Martin"}'
```

::warning
Le jeton `rda_…` donne accès aux documents de **n’importe quel** utilisateur. Gardez-le sur votre serveur : jamais dans du code exécuté par le navigateur, dans un dépôt Git ou dans des logs. Rocket Doc Fusion n’en stocke qu’une empreinte : un jeton perdu se régénère, il ne se réaffiche pas.
::

## Dans la suite Rocket

En mode suite, une autre application Rocket (Rocket Dispatch…) appelle l’API avec un **jeton d’accès de Rocket Auth**, obtenu par *client credentials* pour l’audience `rocket-doc-fusion`, plutôt qu’avec un jeton `rda_…` :

```http
Authorization: Bearer <jeton d'accès Rocket Auth>
X-Impersonate-User: alice@exemple.com
```

Le client appelant (ex. `rocket-dispatch`) doit être lié à une application par un administrateur de Rocket Doc Fusion : champ **Client Rocket Auth** de la page **Applications**. Il a alors les droits de cette application, impersonation comprise, jamais le rôle administrateur. Voir le [README de rocket-core](https://github.com/fayouz/rocket-core#appels-entre-applications-client-credentials).

## Qui suis-je ?

```bash [Terminal]
curl https://fusion.exemple.com/api/me -H "Authorization: Bearer …" -H "Accept: application/json"
```

```json
{
  "user": { "id": "…", "email": "alice@exemple.com", "displayName": "Alice Durand" },
  "application": { "id": "…", "name": "Rocket Dispatch" },
  "roles": ["ROLE_USER", "ROLE_APPLICATION", "ROLE_IMPERSONATION"]
}
```

`roles` contient les rôles **effectifs** de la requête : une application qui impersonne un administrateur n’y voit pas `ROLE_ADMIN`.
