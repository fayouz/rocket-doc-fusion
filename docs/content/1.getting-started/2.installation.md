## Prérequis

Rocket Doc Fusion fusionne, affiche et convertit les documents avec **ONLYOFFICE Docs** (Document Server), lancé par Docker Compose à côté de l’API. Prévoyez pour lui :

- environ **5 Go** de disque pour son image (`onlyoffice/documentserver:9.4.0.1`) ;
- **4 Go de mémoire** au moins, en plus de l’API et de la base ;
- environ une minute au premier démarrage, avant qu’il réponde à son contrôle de santé.

Par défaut, c’est l’édition **Community**, gratuite. Les éditions **Enterprise** et **Developer** demandent une licence, que vous installez depuis l’administration : voir [ONLYOFFICE](/administration/onlyoffice).

## Avec Docker Compose

::steps{level="3"}

### Choisir le secret partagé avec ONLYOFFICE

L’API et ONLYOFFICE signent leurs échanges avec un même secret, d’au moins 32 caractères :

```bash [.env]
ONLYOFFICE_JWT_SECRET=un-long-secret-aléatoire-de-32-caractères-ou-plus
```

::warning
`compose.yaml` fournit une valeur par défaut, connue de tous : changez-la avant toute mise en production.
::

### Démarrer la stack

```bash [Terminal]
docker compose up -d --build
```

Cela lance PostgreSQL, l’API (qui applique les migrations au démarrage), ONLYOFFICE Docs, le worker et le front. Le worker attend qu’ONLYOFFICE soit prêt avant de démarrer.

### Créer le compte administrateur

Ouvrez http://localhost:3400. Tant qu’aucun compte n’existe, Rocket Doc Fusion affiche la page **Configuration initiale** : nom, email et mot de passe (12 caractères minimum) de l’administrateur. La page n’est plus jamais accessible ensuite.

::warning
Tant que le compte n’est pas créé, la première personne qui ouvre l’application peut le créer. Si l’instance est accessible par d’autres avant que vous la configuriez, définissez `SETUP_TOKEN` : la page demandera ce jeton.
::

Vous pouvez aussi créer l’administrateur en ligne de commande :

```bash [Terminal]
docker compose exec api php bin/console app:user:create admin@exemple.com 'un-mot-de-passe-long' --admin
```

### Vérifier ONLYOFFICE

Dans **Administration → ONLYOFFICE**, vérifiez que le serveur répond, avec sa version et son édition. Puis ouvrez **Fusionner** et essayez le modèle d’exemple.

::

| Adresse | Contenu |
|---|---|
| http://localhost:3400 | Application Rocket Doc Fusion |
| http://localhost:8400/api/docs | Documentation OpenAPI de l’API |
| http://localhost:8480 | ONLYOFFICE Docs (chargé par le navigateur pour l’éditeur) |

## Réseau

Trois chemins doivent fonctionner :

| De | Vers | Adresse |
|---|---|---|
| Le navigateur | ONLYOFFICE, pour charger l’éditeur | `ONLYOFFICE_PUBLIC_URL` |
| L’API et le worker | ONLYOFFICE, pour fusionner, convertir et forcer l’enregistrement | `ONLYOFFICE_INTERNAL_URL` |
| ONLYOFFICE | L’API, pour télécharger les modèles, les scripts de fusion et les documents, et envoyer les enregistrements | `ONLYOFFICE_CALLBACK_URL` |

Dans `compose.yaml`, les deux derniers passent par le réseau Docker (`http://onlyoffice` et `http://api`) ; `ALLOW_PRIVATE_IP_ADDRESS=true` autorise ONLYOFFICE à télécharger depuis une adresse privée. En production, `ONLYOFFICE_PUBLIC_URL` est l’adresse HTTPS publique d’ONLYOFFICE, par exemple derrière le même proxy que Rocket Doc Fusion.

## Images Docker

La CI publie deux images sur GitHub Container Registry, pour `main`, `develop` et les tags `vX.Y.Z` :

- `ghcr.io/fayouz/rocket-doc-fusion-api` : API, et aussi le worker, avec la commande `php bin/console messenger:consume async scheduler_default` ;
- `ghcr.io/fayouz/rocket-doc-fusion-front` : front Nuxt.

ONLYOFFICE utilise l’image officielle `onlyoffice/documentserver` (variable `ONLYOFFICE_IMAGE`). L’API et le worker doivent partager le dossier des données (`DATA_DIR`, volume `app_data`) : les modèles et les versions des documents y sont stockés.

## Configuration

### API

| Variable | Rôle | Défaut |
|---|---|---|
| `DATABASE_URL` | Connexion PostgreSQL | — |
| `APP_SECRET` | Secret Symfony, qui signe aussi les adresses données à ONLYOFFICE | — |
| `JWT_PASSPHRASE` | Passphrase des clés JWT (`config/jwt/`, à monter en volume) | — |
| `MESSENGER_TRANSPORT_DSN` | File des fusions | `doctrine://default` |
| `DATA_DIR` | Données de l’application : modèles et versions des documents (`documents/`) | `var/data` |
| `DOC_FUSION_MAX_FILE_SIZE` | Taille maximale d’un modèle ou d’un document, en octets. Au-delà de 32 Mo, augmentez aussi `upload_max_filesize` et `post_max_size` dans `docker/php.ini`. | `20971520` (20 Mo) |
| `ONLYOFFICE_PUBLIC_URL` | Adresse d’ONLYOFFICE vue par le navigateur (script de l’éditeur) | `http://localhost:8480` |
| `ONLYOFFICE_INTERNAL_URL` | Adresse d’ONLYOFFICE vue par l’API et le worker | `http://onlyoffice` dans `compose.yaml` |
| `ONLYOFFICE_JWT_SECRET` | Secret partagé avec ONLYOFFICE (sa variable `JWT_SECRET`), 32 caractères minimum | à définir |
| `ONLYOFFICE_CALLBACK_URL` | Adresse de cette API vue par ONLYOFFICE | `http://api` dans `compose.yaml` |
| `ONLYOFFICE_LICENSE_PATH` | Fichier de licence écrit par l’administration, lu par ONLYOFFICE | `DATA_DIR/onlyoffice/license.lic` |
| `SECRETS_ENCRYPTION_KEY` | Clé de chiffrement des secrets en base (mot de passe de l’annuaire, secrets SSO). Vide : dérivée de `APP_SECRET`. | — |
| `CORS_ALLOW_ORIGIN` | Origines autorisées à appeler l’API depuis un navigateur (regex) | localhost |
| `SETUP_TOKEN` | Jeton demandé par la page de configuration initiale | — |
| `UPDATE_REPOSITORY` | Dépôt GitHub dont les nouvelles versions sont signalées. Voir [Mises à jour](/administration/updates). | `fayouz/rocket-doc-fusion` |
| `UPDATER_TOKEN` | Active la mise à jour en un clic, avec le service `updater` (profil `updater`) | — |
| `RUN_MIGRATIONS` | `1` pour appliquer les migrations au démarrage du conteneur | `0` |

Les variables LDAP sont décrites dans [Utilisateurs et LDAP](/administration/users-ldap).

### ONLYOFFICE

Le service `onlyoffice` de `compose.yaml` est configuré ainsi :

| Variable | Valeur |
|---|---|
| `JWT_ENABLED` | `true` : ONLYOFFICE refuse les requêtes non signées |
| `JWT_SECRET` | la même valeur que `ONLYOFFICE_JWT_SECRET` |
| `ALLOW_PRIVATE_IP_ADDRESS` | `true` : il télécharge depuis l’API, sur le réseau Docker |

Le volume `onlyoffice_data` est monté dans ONLYOFFICE sur `/var/www/onlyoffice/Data`, et dans l’API et le worker sur le dossier de `ONLYOFFICE_LICENSE_PATH` : c’est ainsi que la licence installée depuis l’administration arrive dans ONLYOFFICE.

### Autonome ou dans la suite Rocket

Par défaut, Rocket Doc Fusion est **autonome** : il gère ses comptes (locaux, LDAP, fournisseurs OpenID Connect). Dans la **suite** Rocket, la connexion passe par Rocket Auth, qui gère aussi les utilisateurs, les groupes et l’annuaire :

| Variable | Rôle | Défaut |
|---|---|---|
| `ROCKET_AUTH_URL` | Adresse publique de Rocket Auth. Renseignée : mode suite. | — |
| `ROCKET_AUTH_INTERNAL_URL` | Adresse de Rocket Auth vue par l’API (ex. `http://auth-api` dans Docker) | l’adresse publique |
| `ROCKET_AUTH_CLIENT_ID`, `ROCKET_AUTH_CLIENT_SECRET` | Client OpenID Connect de Rocket Doc Fusion, déclaré dans Rocket Auth | `rocket-doc-fusion` |
| `ROCKET_AUTH_ADMIN_GROUP` | Groupe de Rocket Auth dont les membres administrent Rocket Doc Fusion | `rocket-admins` |
| `ROCKET_LOCAL_LOGIN` | `1` : accès de secours par mot de passe local | `0` |
| `ROCKET_INTERNAL_URL` | Adresse de Rocket Doc Fusion vue par le serveur de Rocket Auth (ex. `http://doc-fusion-api` dans Docker) : Rocket Auth y envoie les déconnexions (back-channel logout) | `ROCKET_PUBLIC_URL`, sinon `FRONTEND_URL` |

En mode suite, se déconnecter de Rocket Auth, ou y être désactivé ou supprimé, ferme les sessions de l’utilisateur dans Rocket Doc Fusion. Les autres applications de la suite, comme Rocket Dispatch, appellent l’API avec un jeton de Rocket Auth (client credentials), à condition qu’un administrateur ait lié leur client à une application : voir [Authentification](/api/authentication#dans-la-suite-rocket).

Voir le [README de rocket-core](https://github.com/fayouz/rocket-core#modes-autonome-et-suite).

### Tâches planifiées

Le worker (`messenger:consume async scheduler_default`) fusionne les documents et lance lui-même, toutes les 5 minutes, la vérification d’ONLYOFFICE, de l’annuaire et des fournisseurs SSO.

Avec LDAP, planifiez aussi la synchronisation de l’annuaire :

```bash [crontab]
*/30 * * * *  docker compose exec -T api php bin/console app:ldap:sync
```

### Front

| Variable | Rôle |
|---|---|
| `NUXT_PUBLIC_API_BASE` | URL de l’API vue par le navigateur. **Vide** : le front relaie `/api` vers l’API (une seule URL publique, pas de CORS). |
| `NUXT_API_INTERNAL_BASE` | URL de l’API vue par le serveur du front, ex. `http://api:80` |

::warning
En production, changez `APP_SECRET`, `JWT_PASSPHRASE` et `ONLYOFFICE_JWT_SECRET`, montez les clés JWT dans un volume persistant et servez le front, l’API et ONLYOFFICE en **HTTPS** : une page HTTPS ne peut pas charger l’éditeur depuis une adresse HTTP.
::
