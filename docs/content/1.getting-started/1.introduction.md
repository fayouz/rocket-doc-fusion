Rocket Doc Fusion est la brique de fusion documentaire du Middleware Rocket. Il remplit des modèles Word (DOCX) avec des valeurs, grâce à **ONLYOFFICE Docs**, puis laisse relire et retoucher le résultat dans l’éditeur ONLYOFFICE avant de le télécharger en Word ou en PDF. Il sert à la fois :

- d’**application** : vos collaborateurs déposent un modèle, remplissent ses variables, retouchent le document fusionné et le téléchargent ;
- de **brique d’intégration** : vos autres applications fusionnent par l’API au nom de leurs utilisateurs, et affichent l’éditeur dans leurs propres pages. C’est le cas de **Rocket Dispatch**, l’application de publipostage : elle prend ses modèles dans Rocket Cloud, les fusionne avec Rocket Doc Fusion, puis diffuse les documents par Rocket Mailer ou Rocket Print.

## Architecture

| Élément | Technologie | Rôle |
|---|---|---|
| API | Symfony 8, API Platform 5, PostgreSQL | Authentification, utilisateurs, applications, modèles, documents et leurs versions |
| Worker | Symfony Messenger et Scheduler | Fusion des documents par ONLYOFFICE, vérifications périodiques |
| ONLYOFFICE Docs | Document Server 9.4 (édition Community par défaut) | Fusion (Document Builder), éditeur dans le navigateur, conversion en PDF |
| Front | Nuxt 4, Nuxt UI 4 | Fusion, documents, éditeur, administration |
| Documentation | Nuxt Content | Ce site, et le changelog |

Rocket Doc Fusion partage sa stack et son socle (comptes, LDAP, SSO, applications, tableau de bord, mises à jour) avec les autres briques Rocket : Rocket Mailer, Rocket Auth, Rocket Cloud et Rocket Print.

## Cycle de vie d’un document

1. Un modèle et des valeurs sont déposés (interface ou `POST /api/documents`) : Rocket Doc Fusion vérifie le modèle, le stocke et crée un document `merging`.
2. Le worker demande la fusion à ONLYOFFICE : un script Document Builder, généré pour ce document, ouvre le modèle, remplace les variables et répète les lignes. Le document passe en `ready`, en **version 1**, ou en `failed` avec le message d’erreur.
3. Le document s’ouvre dans l’éditeur ONLYOFFICE. Quand les éditeurs sont fermés, ou sur **Enregistrer**, ONLYOFFICE renvoie le document modifié : c’est une nouvelle version.
4. La dernière version se télécharge en DOCX, ou en PDF converti par ONLYOFFICE (gardé en cache pour chaque version).
5. Supprimer un document supprime toutes ses versions.

## Documents privés

Un document n’est visible que par son propriétaire, y compris pour les administrateurs : c’est souvent un devis, un contrat ou un courrier personnel. Une application qui fusionne au nom d’un utilisateur crée un document de cet utilisateur, marqué du nom de l’application.

## Traçabilité

Chaque document garde son propriétaire, l’application qui l’a créé, le modèle, les valeurs de la fusion, sa version et la date de sa dernière retouche. Toutes les entités enregistrent leur date et leur auteur de création et de modification (`createdAt`, `createdBy`…).
