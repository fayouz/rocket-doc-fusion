Rocket Doc Fusion confie trois tâches à **ONLYOFFICE Docs** (Document Server) :

- la **fusion**, par un script Document Builder généré pour chaque document ;
- l’**éditeur**, chargé par le navigateur depuis ONLYOFFICE ;
- la **conversion en PDF**.

La page **Administration → ONLYOFFICE** montre son état : serveur joignable ou non, version, édition, adresses publique et interne, état de la licence. **Actualiser** interroge de nouveau le serveur.

## Adresses

| Variable | Adresse de… | Vue par | `compose.yaml` |
|---|---|---|---|
| `ONLYOFFICE_PUBLIC_URL` | ONLYOFFICE | le **navigateur**, qui charge l’éditeur (`/web-apps/apps/api/documents/api.js`) | `http://localhost:8480` |
| `ONLYOFFICE_INTERNAL_URL` | ONLYOFFICE | l’**API et le worker** : fusion, conversion, enregistrement forcé, état | `http://onlyoffice` |
| `ONLYOFFICE_CALLBACK_URL` | cette API | **ONLYOFFICE**, qui télécharge les modèles, les scripts de fusion et les documents, et envoie les enregistrements | `http://api` |

ONLYOFFICE renvoie ses résultats (document fusionné, PDF, document enregistré) sous l’adresse par laquelle on l’a joint ; Rocket Doc Fusion les télécharge par `ONLYOFFICE_INTERNAL_URL`. Toutes les adresses qu’il donne à ONLYOFFICE sont signées (`APP_SECRET`) et valables peu de temps.

## Secret partagé

L’API et ONLYOFFICE signent leurs échanges (JWT HS256) : configuration de l’éditeur, commandes, fusions, conversions et callbacks.

- `ONLYOFFICE_JWT_SECRET` côté API et worker, `JWT_SECRET` côté ONLYOFFICE, avec `JWT_ENABLED=true` : **la même valeur**, d’au moins 32 caractères.
- `compose.yaml` fournit une valeur par défaut, connue de tous : changez-la en production, puis redémarrez l’API, le worker et ONLYOFFICE.

::warning
Avec le secret, n’importe qui pourrait envoyer à Rocket Doc Fusion une fausse version d’un document. Gardez-le aussi secret que `APP_SECRET`.
::

## Édition et licence

| Édition | Image | Licence |
|---|---|---|
| **Community** | `onlyoffice/documentserver` (défaut) | aucune, gratuite ; nombre de connexions simultanées limité |
| **Enterprise** | `onlyoffice/documentserver-ee` | fichier `license.lic` acheté chez ONLYOFFICE |
| **Developer** | `onlyoffice/documentserver-de` | fichier `license.lic` acheté chez ONLYOFFICE |

L’édition affichée est celle du serveur : pour passer en Enterprise ou en Developer, changez l’image (`ONLYOFFICE_IMAGE` dans `.env`, même version que celle de `compose.yaml`) et installez la licence.

### Installer la licence

::steps{level="3"}

### Déposer le fichier

Dans **Administration → ONLYOFFICE**, **Installer une licence** (ou **Remplacer la licence**) : choisissez le fichier `license.lic`. Rocket Doc Fusion vérifie qu’il s’agit bien d’une licence ONLYOFFICE (JSON signé, 64 Ko au plus) et l’écrit dans `ONLYOFFICE_LICENSE_PATH`.

### Redémarrer ONLYOFFICE

ONLYOFFICE ne lit la licence qu’à son démarrage :

```bash [Terminal]
docker compose restart onlyoffice
```

### Vérifier

**Actualiser** : l’état de la licence passe à **Valide**, avec le client, les dates de validité, et les nombres de connexions et d’utilisateurs autorisés (vide : illimité).

::

| État | Signification |
|---|---|
| Aucune licence | Édition Community |
| Valide | Licence en cours de validité, dans ses limites |
| Expirée | Date de fin dépassée : l’éditeur passe en lecture seule |
| Pas encore active | Date de début à venir |
| Invalide ou limite atteinte | Fichier refusé par ONLYOFFICE, ou nombre de connexions atteint |

**Retirer** supprime le fichier : après un redémarrage d’ONLYOFFICE, le serveur fonctionne sans licence.

Le fichier arrive dans ONLYOFFICE par le volume `onlyoffice_data`, monté dans ONLYOFFICE sur `/var/www/onlyoffice/Data` (il y lit `license.lic`) et dans l’API et le worker sur le dossier de `ONLYOFFICE_LICENSE_PATH`. Hors de Docker Compose, faites pointer `ONLYOFFICE_LICENSE_PATH` vers `/var/www/onlyoffice/Data/license.lic` du serveur ONLYOFFICE, ou copiez-y le fichier.

## Supervision

Le worker vérifie ONLYOFFICE toutes les 5 minutes (contrôle de santé et version). Le résultat apparaît dans l’**état des services** du [tableau de bord](/administration/dashboard), sous « ONLYOFFICE Docs ».

## Dépannage

| Symptôme | Cause probable | Solution |
|---|---|---|
| L’éditeur reste blanc, ou « Éditeur indisponible » | Le navigateur ne joint pas `ONLYOFFICE_PUBLIC_URL` | Ouvrez `<ONLYOFFICE_PUBLIC_URL>/healthcheck` dans le navigateur : il doit répondre `true`. Sinon, corrigez l’adresse (DNS, proxy, pare-feu, HTTPS si la page est en HTTPS). |
| La fusion échoue avec l’erreur `-4` | ONLYOFFICE ne joint pas `ONLYOFFICE_CALLBACK_URL` pour télécharger le modèle | Vérifiez l’adresse depuis le conteneur : `docker compose exec onlyoffice curl -I <ONLYOFFICE_CALLBACK_URL>/api/docs`. Sur une adresse privée, `ALLOW_PRIVATE_IP_ADDRESS=true`. |
| Les retouches ne créent pas de nouvelle version, erreurs de callback dans les logs de l’API | Secrets différents : ONLYOFFICE et l’API ne reconnaissent pas leurs signatures | Donnez la même valeur à `ONLYOFFICE_JWT_SECRET` et au `JWT_SECRET` d’ONLYOFFICE, puis redémarrez les trois services. |
| « ONLYOFFICE Docs est injoignable » dans l’administration | L’API ne joint pas `ONLYOFFICE_INTERNAL_URL`, ou ONLYOFFICE démarre encore | Attendez une minute au premier démarrage, puis `docker compose logs onlyoffice`. |
| PDF : erreur `502` | ONLYOFFICE n’a pas pu convertir | Consultez `docker compose logs onlyoffice` ; réessayez après un redémarrage. |
| Licence installée, édition inchangée | ONLYOFFICE n’a pas redémarré, ou l’image est l’édition Community | `docker compose restart onlyoffice` ; vérifiez `ONLYOFFICE_IMAGE`. |

## API

Administrateurs uniquement :

| Méthode | Chemin | Effet |
|---|---|---|
| `GET` | `/api/admin/onlyoffice` | État : `publicUrl`, `internalUrl`, `reachable`, `version`, `edition` (`community`, `enterprise`, `developer`), `license` (`status` : `none`, `valid`, `expired`, `not_started`, `invalid` ; `customer`, `startDate`, `endDate`, `trial`, `connections`, `connectionsView`, `users`, `null` : illimité), `licenseFile` (`installed`, `updatedAt`), `error` |
| `POST` | `/api/admin/onlyoffice/license` | Installe la licence (multipart, champ `file`) ; `422` si ce n’est pas une licence ONLYOFFICE |
| `DELETE` | `/api/admin/onlyoffice/license` | Retire la licence |

```bash [Terminal]
curl -X POST https://fusion.exemple.com/api/admin/onlyoffice/license \
  -H "Authorization: Bearer <jwt administrateur>" -H "Accept: application/json" \
  -F file=@license.lic
docker compose restart onlyoffice
```
